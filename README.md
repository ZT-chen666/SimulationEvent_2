# 椒苗智护

我为农业 AI 产品创新专项赛赛题二开发了“椒苗智护”，面向辣椒育苗棚的单区域灌溉、通风和补光。我以 GD32VF103 RISC-V 官方鸿蒙教程为基础，使用 C 语言和 OpenHarmony LiteOS-M，实现传感采集、控制策略、执行器保护、ST7735S 显示与串口记录。

我以土壤湿度作为灌溉的主要依据，结合温湿度计算的 VPD 近似值，用四条可解释的模糊规则计算需求。灌溉采用短脉冲、等待渗水、重新采样的方式；自动与手动模式共用缺水、采样过期、运行限时和小时预算保护。FUZZY 与 BASE 模式用于比较自适应短脉冲和阈值策略。这些规则由我设计，尚未使用训练得到的机器学习模型。

## 工程结构

- `main.c`：唯一应用入口。
- `app/`：我实现的采集适配、控制、测距换算与运行任务。
- `liteos_m/`、`gd32vf103/`、`startup_gd32vf103.S`、`intexc_gd32vf103.S`：官方教程中的内核、厂商 HAL 和启动代码，我保留了原版权与许可证。
- `Firmware/`、`Hardware/`、`SYSTEM/` 及旧启动文件：我保留的原始裸机框架参考，当前 Makefile 不编译这些目录。它们与现用 HAL 的接口不同。
- `tests/`：我用于验证控制逻辑的纯 C 主机测试，不参与 MCU 采集，也不向运行中的传感器注入预设数据。

## 编译运行

在官方 GD32VF103 RISC-V 鸿蒙实验中，我导入完整工程后使用平台默认的 `riscv64-unknown-elf-` 工具链编译：

```sh
make
```

在本地使用现代 xPack GNU RISC-V 工具链时，我把 GNU make 和编译器的 `bin` 目录加入 PATH，再执行：

```sh
make clean
make -j4 PREFIX=riscv-none-elf- CORE_ARCH_ABI="-march=rv32imac_zicsr_zifencei -mabi=ilp32"
```

产物位于 `build/`，包含 `main.elf`、`main.hex`、`main.bin` 和 `main.map`。显式声明 `zicsr/zifencei` 用于适配新编译器的 ISA 定义，不需要浮点硬件。

## 仿真接线

我选用平台中已经找到的元件，接线如下：

| 元件端子 | GD32VF103 引脚 |
|---|---|
| DHT11 DATA | PA0 |
| YL-69 AO | PA1；DO 不使用 |
| 光敏电阻模块 ADC | PA2 |
| BK_HC_SR04_1 IN / OUT | PA4 触发 / PA3 回波 |
| 水泵 sig | PB0 |
| 植物补光灯 signal | PA7 |
| 风扇 PWM | PA6，1 kHz，开 80% / 关 0% |
| 按键 1 / 2 / 3 | PB12 / PB13 / PB14，另一端接 GND |
| tft_st7735s_1 SCL / SDA | PB6 / PB7，软件 SPI |
| tft_st7735s_1 RES / DC / CS | PA15 / PB4 / PB5 |
| tft_st7735s_1 VCC / BL / GND | 按模块额定值供电；当前采用 3.3 V / 3.3 V / GND |
| 串口终端 RX / TX | PA9 / PA10，TX 可不接 |

各带 VCC/GND 的模块按其额定值供电并共地，ADC 输入应在 0～3.3 V。按键使用内部上拉，按下为低电平。DHT11 的 DATA 若未内置上拉，需要上拉电阻。

我使用的仿真水泵只有一个 `sig`，直接接 PB0；该模型不需要外接 MOS 管、续流二极管、水泵驱动电阻或稳压器。补光灯的 `signal` 直接接 PA7，风扇还要连接 VCC/GND。迁移到实物时，电机和灯具需要独立功率驱动，5 V 超声波回波需要转换到 MCU 可接受的电平。

我采用单块 128×160 的 ST7735S，每行显示 16 个字符，共九行。SCL/SDA 在本工程中是 SPI 时钟和数据线。规则中的 LCD1602 是参考示例，我没有额外添加 LCD1602。2.8 寸和 3.5 寸并行屏不能直接使用这个驱动。

## 标定与操作

我在 `app/board_port.h` 中配置标定端点：土壤默认干 4095 / 湿 0，光照默认暗 0 / 亮 4095。超声波用于测量探头到液面的距离，再换算相对水位；默认满箱 100 mm、空箱 600 mm、容差 50 mm。这些是演示参数，实际使用前需要重新标定。显示的百分比是相对信号，不代表未经标定的体积含水率、lux 或水量。

- PB12 短按：切换自动/手动，立即停泵并清除手动请求。
- PB13 短按：切换育苗/移栽参数；长按 1.5 秒：切换 FUZZY/BASE 策略。
- PB14 短按：在手动模式中请求开关泵；长按 1.5 秒：确认锁存故障。

我设置了 40 ms 防抖，短按在释放时生效。故障确认仍会重新检查水位、传感器有效性和运行预算。

串口使用 USART0、115200、8N1。我将终端 RX 接 PA9，并在平台终端中点击“打开串口”后查看日志；当前程序不接收串口命令，无需发送文字。`STATUS` 包含 `valid`、`distance_mm`、`soil_adc`、`light_adc` 和堆使用量，`STACK` 输出任务栈诊断。

## 当前验证结果

我已完成本版本的本地完整交叉编译：text 43408、data 120、bss 17920 字节，其中 bss 包含 2048 字节启动栈；链接满足 64 KiB Flash / 20 KiB RAM 约束。官方链接脚本的 RWX LOAD 警告仍保留在构建日志中。

我已有的主机测试通过 800049 个控制断言和 520 项测距、液位与保护检查。自建 12 分钟环境模型用于策略比较，结果不作为官方仿真或真实栽培数据。

我记录的修复版平台日志共有 202 条 STATUS，最长一次记录约 153 秒：串口已有输出，温湿度、土壤和光照有效（`valid=7`），堆使用量保持 10340 字节。已有截图显示 TFT 能显示状态文字，完整显示边界、色序和朝向仍需检查。

当前超声波水位输入仍无效：日志中 `distance_mm=0`、`ERR:010`，程序进入保护并保持泵关闭。因此，我尚未完成灌溉全流程、执行器响应与至少 10 分钟连续运行的验收。当前移植的栈填充与水位统计不一致，`STACK peak` 不能可靠表示真实峰值；`overflow=0` 也不能单独证明栈余量充足。

## 来源与本次修复

我以官方 22591 鸿蒙教程的 LiteOS-M、Nuclei 启动及 GD32 HAL 为底座，保留原 21185 框架作为参考。GitHub 相似项目用于方案和接口调研，我没有复制它们的业务策略代码。

本次我在 `board_safe_init()` 中显式调用 `uart_init(115200)`，并把现用和旧版 USART 驱动的 `Usart_Int2()` 引脚修正为 PA2/PA3。运行日志仍使用 USART0 PA9/PA10；USART1 没有启用，因为 PA2/PA3 已用于光照和超声波。我保留了超声波无效时禁止开泵的保护。变更说明见 [release_notes.md](release_notes.md)。
