# 椒苗智护

面向农业 AI 产品创新专项赛赛题二的作品：为辣椒育苗棚提供**单区域**的灌溉、通风与补光控制。

硬件基于 GD32VF103（RISC-V），运行 OpenHarmony LiteOS-M，应用逻辑用 C 语言实现，覆盖传感采集、控制策略、执行器保护、ST7735S 显示与串口记录。工程以官方 GD32VF103 RISC-V 鸿蒙教程为底座。

## 控制策略

灌溉以**土壤湿度**为主要依据，叠加温湿度推算的 VPD 近似值，由四条可解释的模糊规则得出需求。执行上采用「短脉冲 → 等待渗水 → 重新采样」的节奏，避免一次性过量浇水。

自动与手动模式共用同一套保护：缺水、采样过期、单次运行限时、小时预算。另有 FUZZY / BASE 两种模式，用于对比自适应短脉冲策略与固定阈值策略。

规则为手工设计，**未使用训练得到的机器学习模型**。

## 编译运行

在官方 GD32VF103 RISC-V 鸿蒙实验中导入完整工程，用平台默认工具链编译：

```sh
make
```

本地使用现代 xPack GNU RISC-V 工具链时，把 GNU make 与编译器 `bin` 目录加入 PATH，然后：

```sh
make clean
make -j4 PREFIX=riscv-none-elf- CORE_ARCH_ABI="-march=rv32imac_zicsr_zifencei -mabi=ilp32"
```

产物位于 `build/`：`main.elf`、`main.hex`、`main.bin`、`main.map`。其中显式声明的 `zicsr/zifencei` 只是为适配新编译器的 ISA 定义，**不需要浮点硬件**。

## 仿真接线

元件全部取自平台中已找到的型号：

| 元件端子 | GD32VF103 引脚 |
|---|---|
| DHT11 DATA | PA0 |
| YL-69 AO | PA1（DO 不使用） |
| 光敏电阻模块 ADC | PA2 |
| BK_HC_SR04_1 IN / OUT | PA4 触发 / PA3 回波 |
| 水泵 sig | PB0 |
| 植物补光灯 signal | PA7 |
| 风扇 PWM | PA6，1 kHz，开 80% / 关 0% |
| 按键 1 / 2 / 3 | PB12 / PB13 / PB14，另一端接 GND |
| tft_st7735s_1 SCL / SDA | PB6 / PB7，软件 SPI |
| tft_st7735s_1 RES / DC / CS | PA15 / PB4 / PB5 |
| tft_st7735s_1 VCC / BL / GND | 按模块额定值供电，当前 3.3 V / 3.3 V / GND |
| 串口终端 RX / TX | PA9 / PA10，TX 可不接 |

带 VCC/GND 的模块按额定值供电并**共地**，ADC 输入保持在 0～3.3 V。按键使用内部上拉，按下为低电平。DHT11 的 DATA 若模块未内置上拉，需外加一个上拉电阻。

### 与实物接线的主要差别

仿真水泵只有一个 `sig` 信号，直接接 PB0，**不需要**外接 MOS 管、续流二极管、驱动电阻或稳压器；补光灯的 `signal` 直接接 PA7；风扇还需连接 VCC/GND。

迁移到实物时必须补上：电机与灯具的独立功率驱动、5 V 超声波回波到 MCU 可接受电平的转换。

### 显示说明

采用单块 128×160 的 ST7735S，每行 16 字符、共九行。SCL/SDA 在本工程中指 SPI 时钟与数据线。规则中提到的 LCD1602 仅为参考示例，**未额外接入**；2.8 寸和 3.5 寸并行屏不能直接套用本驱动。

## 标定与操作

标定端点在 `app/board_port.h`：

| 项目 | 默认值 |
|---|---|
| 土壤湿度 | 干 4095 / 湿 0 |
| 光照 | 暗 0 / 亮 4095 |
| 水位换算 | 满箱 100 mm / 空箱 600 mm / 容差 50 mm |

以上均为演示参数，**实际使用前需重新标定**。界面显示的百分比是相对信号，不代表未经标定的体积含水率、lux 或水量。

按键操作：

- **PB12 短按**：切换自动/手动，立即停泵并清除手动请求
- **PB13 短按**：切换育苗/移栽参数；**长按 1.5 s**：切换 FUZZY/BASE 策略
- **PB14 短按**：手动模式下请求开关泵；**长按 1.5 s**：确认锁存故障

防抖设为 40 ms，短按在**释放时**生效。故障确认仍会重新检查水位、传感器有效性与运行预算。

串口为 USART0、115200、8N1，终端 RX 接 PA9，在平台终端点击「打开串口」即可查看日志。**当前程序不接收串口命令**，无需发送文字。其中 `STATUS` 输出 `valid`、`distance_mm`、`soil_adc`、`light_adc` 及堆使用量，`STACK` 输出任务栈诊断。

## 当前验证结果

本地完整交叉编译已通过：`text 43408`、`data 120`、`bss 17920` 字节（bss 含 2048 字节启动栈），链接满足 64 KiB Flash / 20 KiB RAM 约束。官方链接脚本的 RWX LOAD 警告仍保留在构建日志中。

主机测试通过 **800049 个控制断言**与 **520 项**测距、液位及保护检查；另用自建 12 分钟环境模型做策略对比，**结果不作为官方仿真或真实栽培数据**。

平台日志共记录 202 条 `STATUS`，最长一次约 153 秒：串口输出正常，温湿度、土壤与光照均有效（`valid=7`），堆使用量稳定在 10340 字节。截图显示 TFT 能正常显示状态文字，但完整的显示边界、色序与朝向仍待检查。

## 尚未解决的问题

**超声波水位输入目前仍无效。** 日志表现为 `distance_mm=0` 并报 `ERR:010`，程序随即进入保护、保持水泵关闭。因此灌溉全流程、执行器响应以及至少 10 分钟连续运行的验收**均未完成**。

另外，当前移植的栈填充方式与水位统计存在不一致：`STACK peak` 不能可靠反映真实栈峰值，`overflow=0` 也不能单独作为栈余量充足的证据。

## 来源与本次修复

底座为官方 22591 鸿蒙教程的 LiteOS-M、Nuclei 启动及 GD32 HAL，并保留原 21185 框架作为参考。GitHub 上的相似项目仅用于方案与接口调研，**未复制其业务策略代码**。相关版权与许可证见 `LICENSE` 及各组件目录。

本次修复包含两点：在 `board_safe_init()` 中显式调用 `uart_init(115200)`；把现用与旧版 USART 驱动的 `Usart_Int2()` 引脚修正为 PA2/PA3。运行日志仍走 USART0 PA9/PA10，USART1 未启用（PA2/PA3 已分配给光照与超声波）。同时保留了「超声波无效时禁止开泵」的保护。
